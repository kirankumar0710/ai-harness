The map: Odysseus, Claude Code, pi and Hermes

Every agent harness is built from the same dozen parts. Odysseus has each one in a small file of its own. Once you know them there, the same parts are easy to find in a much bigger harness, even where it leaves a part out on purpose.

Three design choices the map makes visible

  • Gate or no gate. Claude Code asks before acting, by mode and rule; pi asks nothing and leaves that to extensions; Odysseus has both ends (safe and yolo). Neither is wrong: it is a choice about who is watching.
  • Where commands run. A jail on file paths (as in Odysseus) does not cover a shell. Hermes runs commands in separate backends such as containers; that is the fix for the gap the gate demo shows, where bash reads a file the jail refuses.
  • Memory written by the agent. Hermes writes and refines its own skills and memory. Odysseus lets the model add one line at a time with remember. Both have the risk the memory demo points out: whatever is saved steers every later session.

How to read any harness with this map

  1. Find the model call, then the loop around it. Everything else hangs off that loop.
  2. Find the tool list and the dispatch by name. Count the tools.
  3. Find the code between the tool request and the tool run: that is the gate, if there is one.
  4. Read what goes into the system prompt: rules, memory files, the skills catalog.
  5. Find what happens when the conversation is too long.
  6. Find where messages are written to disk, and what a resume does with a tool call that never got its result.
  7. Find how a second agent is started: as a tool (a sub-agent), or by code outside the loop (orchestration).

Each step has an Odysseus demo that shows the part working: dice (loop), gate (tools and gate), skills, memory, context, durability (sessions and sub-agents) and fleet (orchestration).
