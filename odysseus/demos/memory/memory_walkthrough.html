Memory: the same task, before and after

demos/memory/memory.py runs one task twice in fresh conversations: first with no memory, then with the note the agent saved the first time. A table at the end shows what the note saved.

Goal How it works How to run Sample output Analysis Next steps

Goal

A conversation ends and its messages are gone. Memory is what survives: short facts in AGENT_MEMORY.md, a file in the project that memory.py loads into the system prompt of every new session. The demo shows, with numbers, what that buys:

  1. the agent saves a fact it had to discover, with the remember tool;
  2. a new conversation, sharing no messages with the first, starts with that fact already in its system prompt;
  3. so the same task takes fewer calls, fewer tokens and no wasted steps the second time.

How it works

The project and its hidden fact

The throwaway project has the familiar average() bug, but its checks are not where a model expects tests to be:

# calc.py
def average(values):
    """Return the arithmetic mean of a non-empty list of numbers."""
    return sum(values) / (len(values) - 1)

# checks/check_calc.py   (and an empty checks/__init__.py)
import unittest

from calc import average


class AverageCheck(unittest.TestCase):
    def test_average(self):
        self.assertEqual(average([2, 4, 6]), 4)

Python's test runner looks for files named test*.py, so the obvious command runs nothing:

$ python3 -m unittest
Ran 0 tests in 0.000s
NO TESTS RAN                      # exit code 5

$ python3 -m unittest discover -s checks -p 'check_*.py' -t .
Ran 1 test in 0.000s
OK

Nothing in the project says which command is right. A model has to find out by trying, which is exactly the kind of fact worth remembering.

The two runs

Both runs send the same task, through run_task() in safe mode:

The checks for this project fail. Fix the bug in calc.py and confirm the checks pass. Before you finish, use the remember tool to save anything a future session would need to know about working in this project.
RunBefore it startsWhat it shows
1. without memoryNo AGENT_MEMORY.md. The system prompt has no memory section. The cost of discovering the command, and the note saved at the end.
2. with memorycalc.py is reset to the buggy version, but AGENT_MEMORY.md from run 1 is kept. A fresh conversation: no messages from run 1. The same task, starting from the note.

How the note gets into the next session

The remember tool (from memory_tools()) appends one line to AGENT_MEMORY.md. At the start of every task, run_task() calls build_system_prompt(), which adds the file's contents as a section. In run 2 the model's system prompt contains:

Project memory (AGENT_MEMORY.md):
- Checks live in checks/check_*.py, so plain 'python3 -m unittest' finds none; run them with: python3 -m unittest discover -s checks -p 'check_*.py' -t .

remember writes a file, so the gate treats it as a side effect: blocked in read-only mode, asked about in safe mode. The demo's approver allows file edits, remember, and plain python3 -m unittest commands.

How to run

From the odysseus folder, after pip install -e .:

python3 demos/memory/memory.py --offline   # scripted model, no key needed
python3 demos/memory/memory.py             # a real model; provider and key as in the dice demo

Add --keep to keep the temporary project and read its AGENT_MEMORY.md.

  • The difference is the discovery. Run 1 listed the files, ran plain unittest (0 tests, wasted), then worked out the real command. Run 2 ran the real command first time, because its system prompt already said what it was.
  • The note crossed a conversation boundary. Run 2 shared no messages with run 1. The only link is the file, which is the point of memory.
  • Offline proves the plumbing, not the model. The scripted model follows a script either way. What is real: remember wrote the file, and the file reached run 2's system prompt.

What the live run will test

  • Does run 1 save a useful note, the command and why, rather than a summary of the bug fix that will never matter again?
  • Does run 2 use the note straight away, or rediscover the command anyway?
  • Does run 2 save the same fact again? Duplicates are a cost: every line is in every future prompt.

Something to watch

A wrong note is worse than no note. Memory is loaded into every session and trusted. If the agent saves something mistaken, or the project changes and the note goes stale, every later session starts from the wrong fact. AGENT_MEMORY.md is a plain file: read it, fix it, and commit it like code.

Memory costs context on every call. Unlike a skill, it is never loaded on demand. memory.py caps it at 20,000 characters and keeps the newest notes, but a long memory still makes every request bigger. Keep notes short and few.
