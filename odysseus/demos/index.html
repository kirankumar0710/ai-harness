Odysseus demos

Small, runnable programs that show the odysseus_v2 harness working against a real model. Each demo has its own folder with the script and a page explaining its goal, how to run it and what the output means.

Dice: the agent loop with one tool

Gives the model a single roll_dice tool and two tasks: one the tool can solve (call, result, answer) and one it cannot (the model can only describe what it would do). It shows the full call → tool → result → answer cycle and how the model decides when it is done.

tool callingagent loopany provider

Gate: tools behind the permission gate

Gives the model the six core tools, jailed to a throwaway project, and runs it in each policy mode: read-only (the fix is blocked), safe (an approver allows the edit and the test run) and yolo (deny rules and the path jail still hold). It also shows where the jail stops: shell commands. Runs offline with --offline, no API key needed.

toolspermission gatepath jailruns offline

Skills: instructions loaded only when needed

Gives the model two skills, stored as plain SKILL.md files (a release-note guide and a migration-review checklist), and three tasks: one for each skill and one that needs neither. Shows which skill the model loads for each task, checks the output against the skill's format, and compares the catalog's size with the full skills'. Runs offline with --offline.

skillsuse_skillrun_taskruns offline

Memory: the same task, before and after

Runs one task twice in fresh conversations. The first has no memory and must discover how this project runs its checks, then saves it with remember; the second starts with that note in its system prompt. A before/after table compares model calls, wasted calls and tokens. Runs offline with --offline.

memoryAGENT_MEMORY.mdbefore / afterruns offline

Context: the same long task, before and after compaction

Runs a long task (a chain of files read one at a time) with no size limit, then with a small budget that forces compaction. A chart shows request size growing without it and levelling off with it, and a table checks the answer survived the summary. Runs offline with --offline.

compactiontoken budgetbefore / afterruns offline

Durability: crash, resume, and a sub-agent

Kills the agent's process with SIGKILL in the middle of a tool call, then resumes in a new process from the session log alone, and checks that no step ran twice. Then answers one question twice, reading six files itself or through spawn_agent, and compares the parent's context. Runs offline with --offline.

session logresumesub-agentsruns offline

Fleet: three agents, three projects, at the same time

Gives three small projects (slugify, roman numerals, word counts), each just a test file, to three agents running in parallel with run_fleet(). The demo then runs every project's tests itself and compares wall-clock time with the jobs' total. Runs offline with --offline.

The map: Odysseus, Claude Code, pi and Hermes

The same dozen parts (loop, tools, gate, context, memory, skills, sessions, sub-agents, orchestration) side by side in four harnesses, with what to search for in code you have not read before.

architecturecomparisonreading guide
Demos make real API calls and need a provider and an API key (except with --offline); the unit tests (python3 -m unittest discover tests) do not. Each demo's output/ folder holds the complete output of its recorded runs; save a new one with python3 demos/record.py <demo> [--offline], or run them all with demos/run.sh (offline, live or both), which saves every run to demos/runs/<timestamp>/.
