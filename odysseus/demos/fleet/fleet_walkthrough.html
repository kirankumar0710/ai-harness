Fleet: three agents, three projects, at the same time

demos/fleet/fleet.py gives three small projects to three agents and runs them in parallel with run_fleet(). When they finish, the demo runs every project's tests itself, so a project counts as done only if its tests pass.

Goal How it works How to run Sample output Analysis Next steps

Goal

One agent works on one thing at a time, and most of its time is spent waiting for the model. Independent tasks don't need to wait for each other. Orchestration (fleet.py) is deliberately plain code: a thread pool that runs one run_task() per job, each in its own folder. The plan (which jobs, which folders) stays out here in code; the intelligence stays inside each agent. The demo shows:

  1. the jobs run at the same time: the log lines of three projects interleave, and wall-clock time is close to the slowest job, not the sum;
  2. the jobs stay independent: each agent is jailed to its own folder, with its own conversation and session log;
  3. the result is checked, not reported: the demo runs each project's tests itself after the fleet is done.

How it works

The three projects

Each project starts as a folder that holds only its test file: the tests are the spec. Each agent's task is the same sentence with a different module:

One of the test files, as the agent finds it:

# slugify/test_slugify.py
import unittest

from slugify import slugify


class SlugifyTest(unittest.TestCase):
    def test_words_become_lowercase_and_hyphenated(self):
        self.assertEqual(slugify("Hello World"), "hello-world")

    def test_punctuation_is_dropped(self):
        self.assertEqual(slugify("Hello, World!"), "hello-world")

    def test_runs_of_separators_collapse(self):
        self.assertEqual(slugify("  a -- b__c  "), "a-b-c")

    def test_empty(self):
        self.assertEqual(slugify("!!!"), "")


if __name__ == "__main__":
    unittest.main()

The fleet

results = run_fleet(provider, jobs, mode="safe", approver=approver,
                    max_workers=3, on_event=printer, sessions=True)

    A-->>F: JobResult (ok, answer, seconds, session)
    B-->>F: JobResult
    C-->>F: JobResult
    F-->>D: results, in job order
    D->>D: run each project's tests itself
  • One provider for all three. Providers keep no state between calls, so one instance is shared. run_fleet also accepts a function that makes one per job.
  • One approver, asked one call at a time. In safe mode the approver allows write_file and edit_file (the jail keeps each agent in its own folder), and bash only for python3 -m unittest, with optional 2>&1 or | tail. The fleet calls it under a lock, so a console approver would ask one question at a time.
  • A failing job is a result, not an exception. One job's error cannot stop the others. Ctrl-C cancels the jobs that have not started.
  • Each job has a session log in its own folder (sessions=True), so a crashed fleet can be resumed job by job.

How to run

0. Install the package (once)

From the odysseus project folder.

pip install -e .

1. Offline (no API key)

python3 demos/fleet/fleet.py --offline

2. Against a real model

Set the provider and key as in the dice demo, then:

python3 demos/fleet/fleet.py
python3 demos/fleet/fleet.py --workers 1     # the same jobs, one at a time

To save the complete output, use python3 demos/record.py fleet [--offline].

Analysis

Offline run

3 of 3 projects pass, checked by the demo. The three jobs took 6.2 s between them and 2.1 s of wall-clock time: 3.0 times faster than one after another. The log lines show why: all three agents read their tests at 0.5 s, wrote their modules at 1.0 s and ran their tests at 1.5 s. With a fixed 0.5 s per request and the same four requests per job, the speed-up equals the number of workers. A live run is not that even: jobs take different numbers of turns, and the slowest one sets the wall-clock time.

Parallel is not cheaper. A fleet saves time, not tokens: every job pays for its own requests, whether they run together or one after another. It also multiplies the request rate, so a vendor's rate limit arrives sooner. The transport retries a rate-limited request, which makes jobs slower rather than failing them.

Independent means independent. The fleet refuses two jobs in one folder, but it cannot stop jobs from depending on each other's results. Work that has an order (build the library, then the app that uses it) needs a plan in code that runs the steps in turn, or one agent.
